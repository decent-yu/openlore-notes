长任务智能体如何记住信息：从上下文堆积到可恢复的工作集

长任务智能体需要解决的，是如何在保留证据的同时，让模型每一步只处理当前需要的信息。LangChain 的 Deep Agents 文章给出的核心思路，是由模型外围的执行框架管理信息流：大输入存文件，旧对话压缩，专业指令按需加载，探索过程交给子智能体，稳定偏好跨会话保存。其工程价值在于把“记得住”与“始终放在上下文里”分开，让有限窗口成为可恢复的工作集。

原文以每周研究五家竞争对手为例：数据导出、新闻检索、笔记和多版草稿不断累积，最终排版时仍可能占据窗口。即使检索已经足够精确，工具调用历史和中间产物也会持续增长。因此，RAG 解决资料进入时的选择问题，运行框架还要处理进入之后的生命周期。原文将信息积累导致的准确性和推理表现下降称为 context rot，但没有提供实验数据，无法据此量化退化程度或这些技术的收益。

这些策略通过中间件嵌入“模型决策—工具执行—结果返回”的循环。工具返回处适合拦截大结果，模型调用前适合检查总量和整理历史，运行开始时适合发现技能与读取记忆。由此可以推导：上下文管理应成为调用链的明确职责，不能仅依赖提示词要求模型“保持简洁”。只有框架掌握输入、存储和回读通道，模型才能在精简视图与完整证据之间切换。

首先要把大对象变成可定位的引用。按原文描述，工具结果超过约两万 token 时，FilesystemMiddleware 将全文写入 `/large_tool_results/{tool_call_id}`，向模型返回首尾预览和路径；超过五万 token 的用户消息采用类似方式，保存到 `/conversation_history/`。后续需要某个数值时，再通过 `read_file` 分段读取。这里节省的是每次推理携带全文的负担，代价是额外的文件访问，以及模型判断何时回读的难度。

保存全文并不意味着模型已经正确理解全文。首尾预览可能遗漏中间的关键条件；若模型误以为预览足够，原始数据虽然存在，答案仍可能出错。工程上建议让引用同时携带内容类型、范围、完整性说明和读取入口，并要求关键结论关联到具体证据位置。对于数万行表格，按指标筛选或聚合通常比反复分页更合适；这是针对该场景的设计建议，原文没有展示此类查询能力。

其次，单次结果变小以后，对话仍会缓慢增长。原文中的 SummarizationMiddleware 在每次模型调用前检查 token 用量，默认达到窗口的 85% 时，另行调用模型压缩较早消息，保留近期消息原文，并将被压缩的历史存入 `/conversation_history/{session_id}.md`。新的输入由摘要和近期消息组成；后续再次压缩时，上一轮摘要也会参与。

这形成了“摘要导航、历史取证”的双层结构。摘要有损，历史可恢复，两者不能等同：递归压缩可能淡化例外、遗漏否定条件，甚至把暂定判断变成确定结论。建议摘要优先保留目标、约束、已确认事实、未解决问题及证据路径；最终交付前，对决定性数字和约束回读原始记录。85% 也只是原文给出的默认值。实际配置应为模型输出、下一次工具返回和其他注入内容留出余量，不能将固定比例当作普遍最优解。

专业知识也需要分层。原文的 SkillsMiddleware 在运行开始时扫描技能文件头部，每次调用只注入名称和描述；模型判断相关后，再读取完整 `SKILL.md`。季度报告模板因而可以等到排版阶段才加载。这种渐进披露将常驻成本从完整操作手册降到技能目录，但也把一部分可靠性压力交给了技能选择。描述过于宽泛可能误触发，过于含糊可能漏加载。建议把触发条件写成具体任务和产物，必要时由流程显式加载关键技能，并避免不同技能重复注入大段公共说明。

对已经知道会产生大量探索记录的任务，隔离执行比事后压缩更直接。原文通过 SubAgentMiddleware 配置独立提示词和工具，让研究子智能体读取报告，仅向主智能体返回三条发现。主智能体于是无需承担其全部搜索过程。示例代码实际只配置了 `pull_market_report`，没有展示新闻搜索工具，因此不能据此认定该配置足以完成前述完整竞品研究流程。

子智能体输出越短，主智能体越容易遗漏判断依据。若后续要比较五家公司，仅返回“三条亮点”可能丢失口径、日期和不确定性。更可复用的接口应要求统一字段，例如结论、时间范围、证据路径和待核实项，并将详细材料另存供回读。原文提出子任务可并行、可使用较便宜的模型，但没有给出速度、成本或质量测量。是否值得拆分，取决于任务独立性、调用开销和结果合并难度；需要频繁共享状态的工作未必适合如此处理。

跨会话记忆则承担另一种职责：保存下次仍应生效的信息。原文将其实现为 Markdown 文件，运行开始时读取，每次模型调用注入系统提示，学到值得保留的信息后更新。用户稳定的排版偏好适合这一机制；不断变化的市场数据若也长期注入，容易造成过时信息干扰，并重新扩大常驻上下文。建议记录适用范围和更新时间，区分明确偏好与临时推断，提供纠正或删除入口。并发写入、冲突处理和记忆过期的具体实现，输入材料未说明。

文件由使用者控制，使记忆能够随存储后端迁移到其他模型，但存储格式可移植，不代表不同模型会作出相同解释。切换模型后，仍应检查偏好遵循、工具使用和证据回读表现。对于固定模板、输入很短、只需少量调用的任务，这套分层机制可能增加不必要的复杂度；对于资料多、阶段长、需要反复修订或跨周延续的任务，它更有价值。

落地时，可以先建立统一的资料路径和回读约定，再加入大结果外置与可恢复摘要，随后按任务特点引入技能、子智能体和长期记忆。验证应覆盖摘要后能否找回细节、预览遗漏时是否主动回读、跨公司指标是否同口径，以及旧偏好能否被纠正。上述是建议的验收方向，并非已执行的测试。本文仅依据所提供全文分析；阈值的当前版本适用性、故障恢复能力和实际性能收益均未外部核查，仍属未知。
