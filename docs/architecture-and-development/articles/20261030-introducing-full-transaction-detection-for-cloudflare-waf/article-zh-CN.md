# Cloudflare WAF 推出完整事务检测

![](assets/diagram-1ccd32b9851a.webp)

今天，我们为 Web 应用防火墙（WAF）新增了两项功能：完整事务检测和响应规则。完整事务检测会结合每个 HTTP 请求及其响应进行评估，寻找漏洞被利用的证据。它既能帮助回答“这个请求看起来有恶意吗？”，也能帮助回答“应用处理这个请求后发生了什么？”。随后，响应规则可以在源站响应到达请求者之前将其拦截。

这些防护功能很有价值，因为最新的前沿模型正在发现广泛使用的软件中深藏的漏洞。这既让防守方清楚该修复什么，也为攻击者提供了新的利用途径。近期的 [php2shell](http://blog.cloudflare.com/php-vulnerabilities-waf-protection/) 漏洞说明了其中的风险：一个常见软件组件中的缺陷，就可能使互联网上的众多应用面临威胁。扫描漏洞的 AI 智能体可以极其执着，根据反馈调整攻击载荷，并将漏洞、凭据和权限串联起来。应用的响应可能暴露攻击尝试是否奏效，还可能为攻击者提供信息，帮助他们进一步深入。

检查传入请求仍然至关重要，它可以在可识别的攻击到达应用之前将其阻止。但有些威胁，只有结合请求与源站返回的内容才能看清。同样的可疑输入，如果后续响应暴露了敏感信息，其含义就与请求遭到拒绝或返回错误截然不同。

有了这些新功能，客户可以使用 Cloudflare 托管的防护，也可以结合请求和响应属性，制定自己的策略。这扩展了我们始终开启的应用安全框架，检测结果也会显示在 Security Analytics 中，帮助开展调查。我们首批使用这项功能的托管防护，针对的是最近披露的 php2shell 漏洞。

更棒的是，这些新功能将向所有 Cloudflare 客户正式开放，包括免费套餐用户。

## 仅检查请求还不够

[Cloudflare WAF](https://developers.cloudflare.com/waf/) 通过托管规则、自定义规则和速率限制来保护网站和 API。托管规则针对已知的攻击手法和漏洞提供防护，自定义规则则让团队可以根据 IP 地址、URL 路径、请求头和请求体等参数，制定自己的策略。这些控制措施在请求层面发挥作用，阻止漏洞利用或不需要的流量到达源站。

对于许多威胁，这是采取行动的合适环节。不过，如果将每个可疑请求都视为已经确认的漏洞利用，就会面临两难选择。匹配范围较宽的请求特征可以捕获更多潜在攻击，但也可能产生“误报”，例如匹配到正常流量，进而导致应用无法正常运行。只部署不会触发误报的规则，可以降低这种风险，却可能让更多难以判断的流量有机会到达服务器。

响应提供了此前缺少的证据。现在，Cloudflare 可以将响应与产生该响应的请求关联起来，让检测能够考虑整个 HTTP 事务的结果。

举个例子，假设某个应用允许用户下载文件。攻击者修改文件参数，请求读取允许访问的目录之外的私有配置文件：

`GET /download?file=../../config/database.ini`

请求检查可以识别出这次目录穿越尝试，并在它到达应用之前将其拦截。不过，仅凭请求本身，无法确定应用是否会暴露该文件。应用可能拒绝请求、忽略目录穿越操作，或返回错误。如果请求到达源站，下面这样的响应就能提供更多证据：

```
200 OK
Content-Type: text/plain
[database]
username=app_service
password=EXAMPLE_SECRET
```

**完整事务检测**补上了缺失的一环：它可以将文件访问尝试与具有私有配置文件特征的响应内容关联起来。类似配置的文本可能正常出现在文档或示例下载文件中；如果同时存在目录穿越尝试，就比单独出现其中任何一种信号更能说明敏感数据可能已经暴露。随后，**响应规则**可以在源站响应到达请求者之前，将其替换为 Cloudflare WAF 拦截页面，并返回 HTTP 403。这样就能防止敏感信息落入攻击者手中，从而有效阻止这次漏洞利用。

## 检测与处置在设计上相互独立

完整事务检测扩展了我们今年早些时候推出的[始终开启的检测框架](https://blog.cloudflare.com/attack-signature-detection/)。检测功能分析流量，为请求和响应附加元数据；随后，规则决定如何处理这些结果。

![](assets/diagram-2150df01fab2.webp)

将这两项工作分开，可以让客户先了解流量情况，再设计策略。安全团队可以查看自身流量中的检测结果，了解涉及哪些端点和特征，再选择适合其应用的应对方式。与针对请求的[攻击特征检测](https://developers.cloudflare.com/waf/detections/attack-signature-detection/)类似，检测结果会存储在字段中，自定义响应规则可以访问这些字段，托管检测也可以利用这些字段来拦截流量。

与请求检测字段相对应，我们在平台中新增了以下字段：

| 字段 | 说明 |
| --- | --- |
| cf.waf.signature.response.confidence | 与匹配特征关联的置信度值 |
| cf.waf.signature.response.categories | 与匹配特征关联的类别 |
| cf.waf.signature.response.ref | 特征引用 ID，最多 10 个 |

首批完整事务检测重点用于确认备受关注的漏洞是否遭到成功利用。它会将可疑输入与响应中的信号关联起来，这些信号可能表明漏洞利用已经成功。

我们将逐步扩大覆盖范围，支持其他使用场景，包括检测数据暴露和数据外泄的信号。这对整个互联网都很重要，其意义不局限于某个应用：防护措施可以区分试探行为与攻击造成影响的证据，而针对数据和服务暴露的检测，也能惠及那些没有专门安全团队逐条调优 WAF 规则的客户。

## 针对响应创建规则

如果能够实时采取行动，检测漏洞利用证据才最有价值。自定义响应规则可以在匹配的源站响应到达请求者之前将其拦截，让完整事务检测成为实时防护。不过，它无法撤销源站已经执行的操作。

现在，安全团队可以结合请求和响应属性以及检测结果，决定拦截哪些响应。当拦截规则匹配时，Cloudflare 会将源站响应替换为 WAF 拦截页面或自定义响应。

在 Cloudflare 控制台的“安全 > 安全规则”（*Security > Security Rules*）页面底部，可以找到响应阶段的控制功能，其中包括托管防护和自定义规则。

我们已向所有套餐开放托管规则和自定义规则，包括免费套餐。今后，我们将沿用请求检测的做法：免费套餐的托管检测[重点覆盖备受关注的漏洞](https://blog.cloudflare.com/waf-for-everyone/)，付费客户则可以获得更丰富的检测项目。

## 托管检测

所有客户都可以通过 *Cloudflare Managed Response Firewall Default* 规则集，获得全部事务检测提供的防护。这个规则集支持简单的一键部署，也简化了配置操作。当某个特征匹配时，托管检测会拦截响应，并返回标准 WAF 拦截页面。

![](assets/diagram-ce8951be4582.webp)

你可以编辑 *Cloudflare Managed Response Firewall Default* 的适用范围，只对部分应用运行检测。例如，可以排除某个特定路径，或将检测限制在某个特定路径。付费客户可以在自定义响应规则中使用检测字段，制定更贴合自身需求的策略。

![](assets/diagram-eabe9d9704b0.webp)

## 自定义规则

自定义响应规则旨在让客户完全掌控规则逻辑。例如，一条实用的规则可以在身份验证网关未将请求标记为内部请求时，阻止管理界面暴露：

`http.request.uri.path starts_with "/admin" and not http.request.headers["x-internal-user"][0] eq "true" and http.response.code eq 200 and http.response.headers["content-type"][0] contains "text/html"`

只有当未经身份验证的请求访问 `/admin`，且源站确实成功返回 HTML 管理页面时，这条规则才会拦截。它不会拦截普通的身份验证失败、重定向或与管理界面无关的流量。

![](assets/diagram-52ff4b4a42ce.webp)

所有客户最多都可以创建三条自定义响应规则，支持“记录”（*Log*）和“拦截”（*Block*）操作。自定义响应规则可用的字段和函数，与当前套餐在[自定义请求规则](https://developers.cloudflare.com/waf/custom-rules/)中已经提供的权限一致。目前还不支持基于响应体创建规则。

沿用[攻击特征检测](https://blog.cloudflare.com/attack-signature-detection/)的做法，付费客户还可以通过上文列出的 `cf.waf.signature.response.*` 字段访问攻击检测结果。这些字段可以与其他参数结合使用，例如主机名、URL 路径、源 IP 和请求头，从而只保护某一条路径，或将策略限制在应用的特定场景中。我们目前正在向所有账户逐步开放这些响应字段。如果你还无法使用，请联系你的客户团队。

## 调查匹配的请求

当托管响应规则或自定义响应规则记录或拦截某个事务时，相应事件会显示在 Security Events 中。这样，事件响应人员就可以从任何检测结果追溯到请求的完整上下文，以及采取行动的具体规则。

目前，仅针对请求的规则和完整事务规则会一起显示在同一个分析页面中。在 Security Events 中，响应规则产生的事件归属于“托管规则”（Managed Rules）或“自定义规则”（Custom Rules）服务。你可以在相应的规则列表部分，按特定规则 ID 筛选事件。

## 立即开始使用

完整事务检测现已向所有通过 Cloudflare 代理流量的站点正式开放。要确认你是否已受到保护，请前往 Cloudflare 控制台中的“**安全 > 安全规则**”（**Security > Security Rules**）。如果你想自定义策略，可以先在 Security Analytics 中查看完整事务检测结果，然后创建适合自身应用的响应阶段策略。
