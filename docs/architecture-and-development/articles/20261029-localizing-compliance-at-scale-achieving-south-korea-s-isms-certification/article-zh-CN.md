# 推进大规模业务的本地合规：获得韩国 ISMS 认证

![](assets/diagram-81d4a3795781.webp)

在为期十天的审计中，韩国互联网振兴院（KISA）指定的审计人员与我们一起逐项审查了 80 项控制措施。对于一家总部位于美国、运营全球网络并为韩国用户提供服务的公司来说，这是在韩国获得认证所必须经历的过程。如今，Cloudflare 已在 [ISMS-P 框架](https://isms-p.or.kr/sysm/intro/selectSysmCertDetail.do)下[获得](https://isms-p.or.kr/sttus/cert/selectCrtfctIsueList.do)韩国信息安全管理体系（ISMS）认证。

对韩国客户而言，这不只是完成了一项合规要求。它表明，Cloudflare 的安全与隐私管理工作已经接受审查，审查不仅确认我们是否设有相应的控制措施，还考察这些措施在韩国法律、韩语环境以及韩国监管机构的具体要求下如何运行。

## 韩国用户注册时会看到什么

这项工作最直观的成果体现在 Cloudflare 账号注册页面上。在全球大多数地区，注册按钮上方写着这样一句话：“*继续操作即表示我同意 Cloudflare 的条款、隐私政策和 Cookie 政策。*”

在韩国注册的用户看到的页面则有所不同。系统会根据用户注册时选择的国家，以及 IP 地理定位是否显示其位于韩国，启用韩国版注册流程。在这一流程中，同样的同意内容被拆分为四个单独列明的项目，每项都标注为必选或可选，并链接到完整文本，同时也提供一次性同意所有项目的选项：

- **모두 동의**（*全部同意*）
- **\[필수\] 서비스 약관**（*\[必选\] 服务条款*）
- **\[필수\] 개인정보 수집 및 이용**（*\[必选\] 个人信息的收集与使用*）
- **\[필수\] 제한된 범위의 개인정보 해외 이전**（*\[必选\] 向境外转移有限数量的个人信息*）
- **\[선택\] 제한된 범위의 개인정보 제3자 제공**（*\[可选\] 向第三方营销机构共享有限数量的个人信息*）

三个必选项都是创建账号的硬性条件。在三项全部勾选之前，注册按钮始终处于禁用状态。因此，用户无法在未对每一项明确表示同意的情况下，通过该表单创建账号。可选项只涉及营销许可，不勾选不会影响账号创建，只表示用户选择不接收营销信息。

## 难点：完全不显示表单的注册流程

在我们能够控制的表单中逐项征求同意并不复杂。难点在于，有些注册流程完全跳过了这张表单。

在全球范围内，用户可以通过 Google、Apple 或 GitHub 创建 Cloudflare 账号。这些流程会将用户转交给身份提供商，再带着已经通过身份验证的用户身份返回，全程不会显示我们自己的注册表单，而那四个同意项恰恰就在这张表单上。在这个交接过程中，没有哪个环节能让我们在账号创建之前展示三个必选项、为每项附上完整韩语文本的链接，并要求用户逐项明确表示同意。身份提供商的页面不由我们修改。

我们有两个选择：为一个国家单独增加身份验证后的同意确认环节，或者移除那些会绕过现有同意确认环节的注册方式。我们选择了后者。韩国不提供第三方账号注册，因此，在韩国创建的每个账号都必须经过 Cloudflare 的注册表单，确认所有必选同意项。

我们使用的国家信息与所有 Cloudflare 客户都能获取的信息相同。Cloudflare 根据客户端 IP 地址推断出一个由两个字母组成的国家代码，并将其附加到请求中：在源站可通过 `CF-IPCountry` [请求头](https://developers.cloudflare.com/fundamentals/reference/http-headers/#cf-ipcountry)获取，在 Worker 中则可通过 `request.cf.country` 获取。简化到最基本的逻辑，这个分支判断就是一次字符串比较：

```
// 示意代码：展示判断逻辑，并非 Cloudflare 控制台的实际代码。
export default {
  async fetch(request) {
    // 根据客户端 IP 推断出的两字母国家代码。
    // 与 CF-IPCountry 请求头的值相同。
    // Cloudflare 网络会在收到请求时填入此值，因此我们不需要
    // 自行使用地理定位数据库、查询服务，也不需要额外的往返请求。
    const country = request.cf?.country;
    if (country === "KR") {
      return renderSignUp({
        locale: "ko-KR",
        consent: "itemized",  // 四个独立项目，其中三个为必选项
        socialLogin: false,   // 不提供跳过同意表单的注册方式
      });
    }
    return renderSignUp({ locale: "en-US", consent: "combined", socialLogin: true });
  },
};
```

这段代码没有说明的是，为什么国家代码不能成为唯一的触发条件。我们在文档中说明了 IP 地理定位的局限：它只是一种估计，无法做到精确无误，IP 地址会轮换，也会变更归属。如果某种使用场景关系到能否实现当地要求的目标，就不应将 IP 定位作为唯一依据。韩国居民在海外旅行，或通过 VPN、移动运营商的 NAT 接入时，请求所用的地址可能并不属于韩国。因此，IP 地理定位只决定默认显示哪种表单；用户在注册时选择的国家会覆盖这一判断，后续也以用户选择为准。IP 地址告诉我们请求来自哪里；只有用户自己才能告诉我们他们居住在哪里。区分这两点，才能让用户的同意建立在有意义的确认之上，而非我们的推定。

这是一个小功能，但它需要针对一个国家作出产品决策，并修改账号创建流程。

## 什么是 ISMS，为什么它很重要

ISMS 是一套细致、针对当地要求制定的认证标准。它涵盖安全政策、访问控制、身份验证与权限管理、加密、事件响应、风险管理和灾难恢复。所有这些方面，都要结合个人数据在组织系统中的实际流转情况，以及韩国《个人信息保护法》和相关监管指引进行评估。

获得认证需要先由 KISA 指定的审计人员开展独立审计，再由专门委员会审查。KISA 是隶属于韩国科学技术信息通信部（MSIT）的政府机构。认证有效期为三年，期间必须每年接受审计才能维持认证。

ISMS 认证主要依据韩国《信息通信网络利用促进及信息保护等相关法律》第 47 条设立，认证标准和程序则由该法律的施行令以及 MSIT 发布的 ISMS 认证公告规定。

## 审计检查了什么

Cloudflare 已获得 ISO/IEC 27001、ISO/IEC 27701、ISO/IEC 27017、ISO/IEC 27018 以及其他许多全球公认框架的认证。ISMS 并不取代其中任何一项。它将相同的原则落实到本地环境中，并叠加韩国的监管要求，因此也改变了审计人员检查的内容和方式。

对范围内控制措施的审查，首先从数据流开始。我们提交了详细的数据流图，展示员工访问 Cloudflare 所收集、处理和存储的个人信息的每一条路径。这些数据流本身并非韩国特有。不同的是证据必须采用的形式：审计人员不愿仅凭文字叙述来了解数据如何流转，他们需要能够阅读并据此深入核查的图表。针对每张图，他们都检查了各层访问控制，并测试其有效性。检查涉及我们的内部系统、面向公众的网站、活动页面和 Cloudflare 控制台，覆盖用户数据从首次交互到销毁的整个生命周期。出于保密原因，本文不公开这些图表。

审计还仔细检查了我们征求用户同意时使用的语言和术语，包括注册页面上的具体措辞、每项告知的结构，以及各项目是否单独、清晰地呈现。这正是 ISMS 框架旨在揭示的细节。

## 为什么整个过程长达一年半

部分原因在于审计周期的安排。一次 ISMS 审计覆盖一个年度，所有证据、文档和系统都必须反映该年度的情况。我们的准备工作跨越了一个审计年度，延续到了下一个年度。这意味着，我们需要为新的审计年度重新翻译更新后的政策、重新收集和评估证据、重新发布更新后的隐私政策，还要将营销和网站团队在此期间引入的格式与设计变更纳入其中。

## 证书覆盖哪些范围

KISA 以服务边界界定认证范围，而不是逐一列出范围内的产品。提交给 KISA 的《范围声明》从三个方面描述了这一边界：

- **组织与运营边界**：运营该服务的 Cloudflare 实体、团队和流程；
- **基础设施边界**：获认证服务所运行的网络和平台；
- 在 ISMS 控制措施下，纳入该边界的**信息资产与个人信息流**。

如果客户使用的某项 Cloudflare 产品通过这一获认证的服务边界交付，也就是说，它运行在同一个获认证的平台上，由同一批获认证的团队运营，并受同一套 ISMS 管理，那么它就在证书覆盖范围内。证书由 Cloudflare, Inc. 持有。

这与大多数采购团队接触的报告形式有所不同。SOC 2 报告或 ISO 27001 证书会描述其覆盖的系统，并列明所包含的服务，因此可以通过在清单中查找产品来确认是否受其覆盖。ISMS 证书没有这样的清单。它是否覆盖某项产品，取决于该产品的交付路径，无论证书中是否提到产品名称。

## 这对客户意味着什么

对于在韩国运营的组织，这项认证为法务、安全和采购团队提供了一个符合当地要求的保障基准，与 Cloudflare 更广泛的合规认证相互补充。ISO/IEC 27001 和 SOC 2 体现整体安全状况，ISMS 则反映韩国特有的法律与监管要求。这一区别对于第三方风险审查，以及团队为自身合规评估作准备，都很重要。

可以在 [KISA 的获认证组织公开名录](https://isms-p.or.kr/sttus/cert/selectCrtfctIsueList.do)中找到 Cloudflare 的记录。这是一项独立、可核实的确认信息，可在风险审查中引用。更广泛的隐私与数据保护资料可在 Cloudflare [信任中心](https://www.cloudflare.com/trust-hub/)查阅。

对 Cloudflare 开展供应商审查时，一个经常导致进展停滞的问题是：正在使用的某项产品是否在认证范围内。证书不会通过产品名称回答这个问题，因为其中没有列出任何产品。它通过边界来回答：只要该产品通过获认证的服务交付，就在认证范围内。

对于跨地区管理安全事务的跨国团队，这项认证确认：Cloudflare 的管理工作已经在亚洲最重要的数字市场之一接受了当地要求的审查，而不只是按全球规模的业务需求来设计。

## 为每个人构建更好的互联网

与我们接受的其他保障审计相比，ISMS 并不是更难获得的认证，而是对细节和具体情境有更多要求。它围绕某个特定地区的监管需求而建立，要求企业真正投入资源，理解并落实这些需求，而不只是将其对应到一套通用控制框架上。

经历这一过程，让 Cloudflare 更能服务全球。它促使我们认真思考：在特定的本地环境中，使用当地语言、遵循当地对用户同意的要求以及数据保护要求，为用户提供服务，究竟意味着什么。它也推动我们将这些要求落实到产品的实际行为中，而不只是写进文档。

这与我们一直努力实现的目标一致：帮助构建一个对每个人都更好的互联网，既包括监管要求明确易行的地区，也包括世界各地的其他地方。
